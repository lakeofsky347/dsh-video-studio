# 影片首页、Session 与代理协作

点击 DSH 侧栏的映流入口进入影片首页。这里管理本地影片与已有会话的关系；打开工作台后查看分镜、帧、源码和声音。工具结果卡片的指定帧入口直接打开工作台，不经过首页。

## 选择已有会话的影片

1. 在首页「查看范围」选择会话，可搜索名称或工作区。
2. 工程卡片标明「当前工程」或「已关联」。打开工作台只是查看，不切换模型目标。
3. 选择「继续会话」；若当前使用另一部影片，按钮明确显示「设为当前工程并进入会话」。

一个 Session 保留多个关联影片，但只有一个当前工程。一个影片可以关联多个 Session。工具未提供 projectId 时操作该 Session 的当前工程。

## 给已有工程关联会话

从工程卡片或工作台点「关联会话」，选择已有会话。若会话当前制作 A，弹窗说明将切换为 B，提交一次即完成。A 保留关联。绑定不会发送消息或启动模型，也不会产生影片内容版本。

会话或继承其工程的子代理正在执行时，切换当前工程需等待回合结束。已启动的导出继续使用原工程快照。解除某个关系保留工程与聊天记录；解除当前工程后不自动指定其他工程。

## 子代理与团队成员

默认列表显示普通用户会话。展开「显示子代理／团队任务」后，可以查看宿主已发现的子代理和活动团队成员。选择根会话会刷新其投影目录，未打开的任务可从真实宿主目录发现。

子代理默认沿实际委派父子链使用最近上级的工程；团队成员采用同一规则。普通 fork 的父会话仅表示历史来源，不继承影片。一个子代理可有专属绑定，也可以显式传 projectId 操作已授权协作的工程。

子代理建立专属关联后，其他成员的工程不变。解除专属当前工程会保留显式空选择，阻止悄悄回到父会话工程；需要继续制作时重新关联。

团队协作的建议分工为：主会话整理简报和镜头顺序，成员分别负责指定镜头源码、声音或画面检查。每个写入者先读取工程，再提交局部修改与 expectedRevision。版本过期后重新读取并合并，而不是覆盖其他成员已提交的内容。

以上为 video_project 的参数。其回执中的 projectId、revision 和 shots 用于下一步 video_update：

```json
{
  "projectId":"回执中的工程 ID",
  "expectedRevision":12,
  "update":{
    "shotPatches":[{"id":"指定镜头 ID","patch":{"title":"新的镜头标题"}}]
  }

```

子代理 create 默认复用已继承工程；确实需要新影片时设置 forceNew:true。工具回执区分 callerSessionId 与 ownerSessionId。Job 的进度、结果与取消仍属于实际调用者。点击「返回会话」使用 DSH 的子代理专用地址，不把子代理 ID 当普通会话打开。

这些能力复用 DSH 的会话、代理、团队和 Jobs 服务。插件不负责创建团队，也不要求额外的团队数据库。外部代理运行时需要由宿主向其提供视频工具；当前会话里不可见的工具不会由影片首页自动安装或启用。

## 数据与升级

影片内容保存在可搬运工程目录；会话关系保存在当前宿主工程基目录的 sessions.json。v2 索引记录每个会话的 currentProjectId、relatedProjectIds 与 updatedAt。旧版索引首次启动自动迁移，影片 schemaVersion 仍为 1。

旧工程中的 sessionIds 是兼容数据，不作为重启自动重绑依据。复制影片不继承活动关联，移动或导入工程不会激活来源机器的会话。

源码草稿按工程和镜头保存在客户端存储中；回首页和切会话不会执行草稿。参数保存失败时保留本地内容并显示恢复入口。已保存源码与素材仍在影片工程内。
